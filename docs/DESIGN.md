# 《牌语四季》设计文档

> 版本：**v1.0（2026-10-13）** · 状态：**形态定稿（方案 B），M0 开发中**
> 前身：Solstice 场景引擎（归档：分支 `archive/solstice-scene-engine` + `docs/archive/`）
> 定位一句话：**一款收集展示型卡牌游戏**——收集/合成四季纸墨卡牌，摆上卡桌触发节气事件；单机离线买断，Steam 发售（T1 桌面化 + 卡桌作壁纸）。

---

## 0. 定位与体验支柱

1. **收集即玩法**：图鉴完成度是主目标；150–300 张卡面由 AI 管线量产（合规留档）
2. **卡桌会活**：摆上桌的卡牌组合触发词条/事件（"松 + 鹤 = 延年"）；卡桌延续桌面基因，T1 可设为壁纸
3. **节气节律**：24 节气真实日历驱动每日事件与限定卡——与"至日"出身一脉相承
4. **零平衡黑洞**：无对战数值；经济节律（产出/消耗曲线）离线计算可验证——适配"AI 开发 + 用户裁决"模式

**非目标**：对战/多人/服务端/账号/内购/移动端（延续原非目标清单）。

## 1. 核心循环

```
 获得卡牌（事件奖励 / 签筒抽取 / 合成）
        ↓
   图鉴收集进度 ←—— 墨料（通用货币）
        ↓                              24 节气日历（真实日期）
   卡桌摆放 ——组合词条/事件触发——————→ 节气限定卡与目标
        ↓
   收益 → 再投入合成/抽取 →（循环）
```

- **获得**：墨料在签筒抽卡（随机 + 图鉴进度定向保底）；节气事件直接赠卡
- **合成**：低阶卡 ×N + 墨料 → 高阶卡（1→2→3 阶）；季节合成（春卡×3 → 立春限定）
- **摆放**：卡桌网格自由摆放/旋转；卡牌间满足组合条件 → 点亮词条、触发事件、掉落收益
- **节气事件**：按真实日期开启（惊蛰/夏至/霜降…），期间限定卡池与目标；离线进度照算

## 2. 卡牌数据模型

```
Card {
  id          "card.mt-pine.2"        // card.<主题>.<阶>
  name        {zh, en}
  suit        mountain|water|plant|bird|beast|person|sky|artifact   // 8 系
  season      spring|summer|autumn|winter|all
  rank        1|2|3                   // 阶：合成链层级
  image       卡面（studio 产，引擎绘制统一边框/框饰）
  combos      ComboRef[]              // 参与的组合（另一份 combos.json 定义）
  flavor      {zh, en}                // 一句话卡语
  credits     模型|prompt 出处|日期    // Steam AI 披露留档
}
Combo { id, cards[], effect(词条|事件|特效), name{zh,en} }
```

- **组合示例**：`松(plant/winter) + 鹤(bird) → 延年`（词条：墨料产出 +10%）；`夏至日摆出 3 张水系 → 限定卡「荷风」`
- 卡牌内容包 = 声明式 manifest（继承 Solstice 包系统思想：`cardpack.schema.json`，工坊 UGC 的先天形态）

## 3. 技术架构（Vite + TypeScript）

```
solstice/
├─ src/                      # 游戏（Vite+TS，vanilla TS + DOM，零运行时框架）
│  ├─ main.ts                # 装配启动
│  ├─ core/                  # 纯 TS 领域逻辑：cards / economy / combos / events / save
│  ├─ ui/                    # 视图：cardtable(卡桌) / codex(图鉴) / draw(签筒) / craft(合成) / hud
│  ├─ data/                  # 内置卡牌内容包（JSON，声明式）
│  └─ styles/                # 纸墨主题令牌（继承归档 DESIGN 的 --paper/--ink/--seal）
├─ shared/                   # 契约：card.schema.json / combos.schema.json（生产者与消费者共读）
├─ studio/                   # 卡面生产线：contract(卡面合同) / tools(gen.py 沿用) / frames(产出)
├─ dev/                      # 双机同步（现役）
└─ docs/
```

- **立场延续**：UI 零框架（DOM+CSS 令牌）；领域逻辑纯 TS 可单测；存档 JSON 版本化迁移
- 存储：`localStorage` 起步（键 `ps.save.v1`），T1 迁文件存档
- 立项工程：`npm create vite@latest` vanilla-ts 模板 + `tsconfig` strict；**首次需要 package.json**（用户裁决 Vite+TS 时已解除零构建红线）

## 4. 素材线（卡面生产，替代原远景/材质线）

- **风格锚**：S1（新海诚/吉卜力，已裁决锁定）——卡面一律垫 S1 及其裁片
- **规格**：竖版 3:4 画芯 1024×1365（引擎统一绘制边框/角饰/文字——素材只管画芯，无文字无水印）
- **规范**：单主体居中、四季色调按季节段、平光（无自带时辰）、系列内构图节奏变化、避免人脸特写（深度/抠图稳定）
- **合规**：逐张 prompt 留档（`studio/jobs/`），credits 进卡数据
- 详见 `studio/contract/card-faces.md`（卡面生产合同）

## 5. 里程碑

| 里程碑 | 内容 | 验收 |
|---|---|---|
| **M0 骨架**（进行中） | Vite+TS 工程 + 卡牌数据模型 + 图鉴/卡桌静态版 | 打开即见 20 张卡可摆 |
| M1 收集闭环 | 签筒抽取 + 墨料经济 + 合成 + 图鉴进度 + 组合词条 | 完整玩 30 分钟不打断；存档可清 |
| M2 节气事件 | 24 节气日历事件 + 每日目标 + 限定卡池；内容 60→150 张 | 真实节气当日触发正确 |
| M3 桌面化 | Tauri 2 壳 + 卡桌作壁纸（WorkerW，归档文档可复用）+ Steam 工坊（卡组分享） | 72h 挂机稳定 |

## 6. 风险

| 风险 | 对策 |
|---|---|
| 收集玩法深度不足 → 留存弱 | 组合词条系统做"发现感"；节气更新节律；图鉴目标分层 |
| 300 张卡面的风格漂移 | 风格锚合同（S1）+ 逐张留档退回机制（原目标帧合同经验） |
| 经济通胀/死锁 | 产出-消耗曲线离线表格化，进 DESIGN 附录可调 |
| 过度工程化（老毛病） | M0–M1 不做工坊/不做模组；包 schema 只加不改 |
