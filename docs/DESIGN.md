# Solstice 设计文档

> 版本：**v5.3（2026-10-13）** · 状态：**需求基线 + 技术方案定稿**；M1 简笔画场景开发中；素材生产 = 混合分层路线（§2.5，全本地部署模型）；UI 游戏化 + Actor 协议落地（§2.8）
> 定位一句话：**桌面 2.5D 场景搭建游戏**——玩家用风格统一的元素组合出随昼夜/天气/季节变化的"活场景"，内含壁纸模式与图片素材库等功能模块
> 技术栈（锁定，v5.3 修订）：**TypeScript 全栈 = Tauri 2 壳 + 2.5D 渲染（WebGL2 程序化背景 + Canvas2D sprite 叠加 + 深度视差）**；素材 = 部署模型 2D 生成（混合分层，§2.5）+ 程序化占位
> **v5.3 裁决**：放弃 3D/Babylon 线，全面统一 2D 生成素材（用户 2026-10-13 拍板；理由：部署模型全线 2D 出图、风格天然统一、Babylon 素材线与生成式素材割裂）
> 仓库 github.com/quoteZZZ/solstice

## 0. 需求基线

### 0.1 产品本质
**游戏**（桌面玩具游戏）。"壁纸"是游戏提供的一种输出形态（功能模块），不是产品定位。

### 0.2 核心体验四循环
1. **观赏**：世界自己活着——昼夜循环、天气、季节、动物行为
2. **搭建**：元素库 → 选中/放置/缩放/配色 → 保存自己的场景
3. **陪伴**：宠物行为与互动
4. **收集**：元素包 / 风格 / 图片素材（工坊，长期）

### 0.3 质量四标准（硬指标）
| 标准 | 保证手段 |
|---|---|
| 风格化 | StyleSystem：渲染器强制一致；多风格预设（简笔画/卡通/水彩/写实）一键切换 |
| 高清 | 程序化/矢量分辨率无关；图片素材源图 ≥2048px（底图 4K） |
| **优美** | **混合分层素材线（§2.5）**：部署模型整图直出远景 + 目标帧合同锁美术基准 + 渲染氛围层（LUT/雾/辉光） |
| 灵动 | 代码层：风摆着色器、sprite 帧动画、粒子、时辰联动 |
| 快速起量 | 程序化 + CC0 双源（**v5.1 降级为开发期占位资产**）+ 图片素材库 |

### 0.4 功能模块总表
| # | 模块 | 里程碑 | 说明 |
|---|---|---|---|
| F1 | 活场景引擎 | M1（进行中） | 昼夜/天气/季节 + 多风格渲染后端 |
| F2 | 场景搭建器 | M3 | 元素放置/吸附/存档/读取 |
| F3 | 宠物伴侣 | M4 | sprite 帧动画 + 行为状态机 + 互动 |
| F4 | **壁纸模式** | T1（桌面化阶段） | 把当前场景设为桌面壁纸（WorkerW 嵌入，机制已验证 ✓） |
| F5 | **图片素材库** | M2 起逐步 | 图片元素与 AI 生成素材纳入素材体系，经风格化滤镜统一 |
| F6 | 工坊 | T2 | 场景/元素/风格 UGC |

### 0.5 非目标
- ❌ 运行时 AI 对话；❌ 账号云同步；❌ 移动端（T2 后评估）

### 0.6 待用户确认项（默认按本文执行）
1. M1 验收清单（§1.4）有无增删
2. 宠物交互范围（M4：喂食/抚摸是否够）
3. 图片素材库的首批来源（AI 生成 / 用户导入 / 两者）

## 2. 架构（TS 全栈，v5.3 2.5D 定稿——3D/Babylon 线移出主线）

### 2.1 分层总览
```
┌─ 壳（T1）：Tauri 2 —— 窗口/托盘/Steam（壁纸模式=F4 嵌入能力）─┐
│                                                                │
│  ui/      游戏 HUD（Dock+纸签面板） · 设置中心（玩家/开发者两层） │
│           · 场景编辑器（圆盘/Gizmo/菜单） · 信息纸签              │
│  plugins/ base · mountains · weather · trees · horses · presets │
│           · info · （图片素材库 F5 → 元素提供方之一）            │
│  core/    composer（WebGL 程序化后端）                          │
│           sketch（简笔画 2D 后端）                               │
│           style（StyleSystem：风格预设分发）                      │
│  kernel   i18n · 存储 · 上下文总线（太阳/调色/天气）· 注册表+仲裁  │
└────────────────────────────────────────────────────────────────┘
```

### 2.2 渲染后端协议（StyleSystem 落地点）
- composer 主循环为**唯一指挥**：构建 st（仲裁状态）→ 按 `S.style` 分发：
  - `default` → WebGL 程序化管线
  - `sketch` → core/sketch.js 2D 画布
- 后端契约：`init() / frame(st, t)`，吃同一份 st（太阳/卡片/天气/夜晚系数），编辑器命中区由后端暴露几何（lakeBox/horseBand）
- 新风格 = 新后端或后端内的预设分支，**元素与交互零改动**

### 2.3 目录规范（红线：新文件必须归位）

**完整目录树、命名规则与归位决策表见 [`STRUCTURE.md`](STRUCTURE.md)（唯一真源）**；本节只留形状摘要：

```
app/        运行时：游戏本体 + 壁纸模式（发布物）—— js/{kernel,core,ui,plugins,vendor,shell} + assets/{packs,models,images}
shared/     跨域契约：pack manifest schema + 图层类/卡槽表（运行时与生产线共读，零逻辑）
studio/     素材生产线（离线）：contract(要什么) · jobs(怎么生成) · tools(怎么跑) · frames(跑出什么) · work(中间件，gitignore)
dev/        工程基建：双机同步（sync）+ 机制验证留档（spikes）
docs/       文档：DESIGN(设计) · STRUCTURE(目录) · PACKS_GUIDE(素材) · SYNC(协作)
site/       落地页资源；根级 index.html 为 Pages 入口（硬约束，见 STRUCTURE §8）
```

三分法：**会进发行包的 → `app/`；产出素材的 → `studio/`；双方共读的定义 → `shared/`**。
加文件前先查 `STRUCTURE.md §4` 归位决策表；依赖方向单向（见 `STRUCTURE.md §5`）。

### 2.5 素材体系（混合分层路线，v5.1 定稿）
> **裁决记录**：2026-10-13 用户确认"CC0 双源 + 元素级 AI 生图产出简陋难看"，素材生产切换为**混合分层路线**（方案 A）。M1 简笔画线不受影响（程序化，独立风格线）。

| 层 | 生产方式 | 风格统一手段 |
|---|---|---|
| **远景/主视觉** | 云端顶级模型（Nano Banana 2 / Seedream 5.0 Pro / LiblibAI）**整图直出** 16:9 ≥4K → 深度带拆层（3–5 层）+ Depth Anything 深度图 | 目标帧合同 + 参考图锁风格 |
| **前景/交互元素** | 本地 FLUX klein 4B（5060 8GB fp8 可跑）sprite 化：单图生成 → BiRefNet 抠图 → 透明 PNG | TF01 参考图（垫图/IP-Adapter）+ 统一中性顶光 + 运行期令牌 LUT 调色 |
| **天气/昼夜** | **不重绘素材**：色彩分级 LUT + 光照叠加层 + 程序化粒子 | 渲染器即风格 |
| 程序化 | 代码绘制（简笔画线/占位） | 渲染器即风格 |
| 3D 低模 | ~~CC0 双源~~ **v5.3 移出素材线**（2.5D 定稿；Quaternius 仅存 spike 工具资产；Kenney 2D/UI 粒子可作开发期占位） | — |

**公共环节（红线）**：
1. **目标帧合同**：优美线素材开工前必须先有经用户裁决锁定的目标帧（8 张关键帧，`studio/contract/target-frames.md`）；成图与目标帧显著偏离 = 退回。TF01 兼作黄金帧基准。
2. **渲染氛围层**：色彩分级 LUT、雾、太阳光辉、辉光进正式管线——素材只负责造型，氛围由渲染承担。
3. 图片元素入素材库登记来源/许可/适用风格；素材留档 prompt+来源，备 Steam AI 披露审查。

### 2.8 Actor 协议与游戏 HUD（v5.2 定稿，2026-10-13）
> **裁决背景**：用户多次纠偏"本质游戏不是壁纸"，且后续要扩展可操作、可动的桌面宠物类功能。图层卡片模型撑不起交互实体，故升级协议；**游戏窗口为主形态，壁纸 = 场景的一种输出形态**（WorkerW 机制不变）。

**Actor 协议**（实体 = 卡片的演进超集，向后兼容）：
- 插件 manifest 声明 `actors:[{ id, interactive, behaviors:['wander','gallop','respond',…] }]`
- 状态同存 `S.cards[id]`（pref 三态/参数），`registry.cards()` 合并两者 → 编辑器右键/显隐/设置中心**对 Actor 一视同仁**；`registry.actors()` 为专视图
- 交互事件总线：`ctx.emit('actor:click', {id, index})` —— 点击回应由插件自己实现行为；宠物 M4、蝴蝶、鸟全部走同一协议，**这就是功能扩展的插槽**
- 首个参考实现：`plugins/horses.js`（wander 漫步 / gallop 奔跑 / respond 被点击跳跃；2D canvas 叠加渲染，命中矩形写 `st.horsesRects` 供编辑器）

**游戏 HUD**（ui/hud.js，壁纸态 `?ui=0` 整体不渲染）：
- 底部 Dock 按钮**注册制** `K.hud.add({id, icon, labelKey, pop|fn, order})`，默认七键：天气/时间/搭建/伙伴/场景/编辑/设置；插件可贡献按钮（宠物插件注册"伙伴"键的占位已留）
- 弹出面板 = 纸签 popover（单例、点外关闭）；元素架 = 物品栏骨架（分类分组 + 缩略图），M3 拖放放置的入口
- 场景簿 `K.scenes`：场景 = 环境(天气/时辰/亮度/预设) + 全部卡片与 Actor 状态，3 槽快照存 `lw.scene.v1.<i>` —— 核心循环②"保存自己的场景"的一级落地，也是工坊 UGC 的单元

**纸墨主题**（与 M1 简笔画场景同一视觉语言）：
- CSS 令牌：纸 `--paper`（昼 `#fbf6ea`/夜 `#1e263a`）、墨 `--ink`（昼 `#3a342c`/夜 `#dee8f5`）、印章红 `--seal:#b5432f`、点缀 `--acc` 随天空顶色
- 全部浮层（Dock/纸签/面板/圆盘/菜单/Gizmo）统一令牌 + 衬线标题；`body.night` 由信息纸签每帧按 `st.night` 切换，0.8s 过渡
- 设置中心拆两层：玩家层常显；`dev:true` 的工程参数（视差/FPS）仅 `?debug=1` 渲染
