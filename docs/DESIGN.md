## 1. 产品概述

### 1.1 一句话愿景

**一个微内核壁纸引擎 + 一个创意工坊生态**：底座只负责合成、上下文与插件管理；画面里的一切——太阳、云、山、树、雨雪、宠物、彩蛋、预设——都是可插拔的卡片插件，与你的真实时间、天气、季节同步活着。

### 1.2 核心决策记录

| # | 决策点 | 结论 | 理由 |
|---|---|---|---|
| D1 | AI 角色 | 仅用于开发管线（离线生成素材），运行时零 AI 调用 | 免运行时成本 |
| D2 | 素材模式 | 预生成素材库 + 用户挑选；无服务端按需生成 | 零服务器/审核/延迟 |
| D3 | **架构** | **微内核 + 全面插件化**（§3）：官方内容也用插件格式（自举） | 生态可扩展；工坊即插件 |
| D4 | 冲突仲裁 | 元素卡三态偏好；**光照永远跟真实**（§4.2） | "隐藏太阳但真实晴天"类冲突 |
| D5 | 渲染 | 单 WebView + 原生 WebGL2 + GLSL | CEF/WebView2 直接跑 |
| D6 | 语言 | TypeScript/JS 一门；现 JSDoc 零构建，esbuild 按需 | 最小技术栈；Go 已否决 |
| D7 | 差异化 | 精灵宠物 + 会同步真实世界的场景 | 无竞品组合 |
| D8 | **发布路径** | **直接独立 Steam 应用**（Tauri 壳自绘壁纸），**不走 WE/Lively 平台**（仅作开发测试工具）；应用集成**自家 Steam 创意工坊**供素材包替换/上传 | 掌控全链路与商业化 |
| D9 | 平台 | Windows 优先 | iOS 不开放；Android 后置 |
| D10 | 开发环境 | 云开发：GitHub 真源 + Pages 预览 + 云端生图/深度图 | 用户非主力机 |
| D11 | **国际化** | **首版中英双语**：UI 字符串表 + 插件 manifest 双语字段 + 商店页双语 | Steam 全球分发 |
| D12 | 插件安全 | 声明式优先；代码级插件延后且必须 Worker 沙箱（§3.5） | 工坊内容不可信，防过度工程 |

### 1.3 三大价值支柱（对外话术）

1. **深度视差** —— 第一眼的 wow，传播载体
2. **真实时辰光照** —— 按纬度算日出日落，"它和我的生活同步"
3. **天气同步 + 宠物 + 插件生态** —— "外面下雨壁纸在下雨、宠物去躲雨，而这一切都可以被工坊素材替换"

## 3. 架构总纲：微内核 + 全面插件化 ★

### 3.0 设计思想

产品本质是**平台**：底座小而稳，内容无限可换。两条自举原则：

1. **官方内容 = 插件**：太阳、山峦、雨雪、宠物全部打包成与创意工坊完全相同的插件格式——狗粮自吃，生态管线从第一天就是唯一管线
2. **声明式优先**：90% 的插件（素材卡）只需 PNG + manifest.json，零代码；代码级插件是例外且必须沙箱

**务实红线（防过度工程，最重要的一节）**：
- 内核只暴露 **6 个服务**（§3.1），API 面积冻结，扩展只加不改
- T1 不开放任何第三方代码执行——工坊先只收声明式包
- manifest 带版本号（api:1），稳定前不承诺兼容

### 3.1 微内核职责（底座，仅此六项）

| 服务 | 职责 |
|---|---|
| ① 合成器 | 图层栈按类排序（附录 C）、渲染循环、深度视差、性能治理（fps 上限/hidden 跳帧/低功耗） |
| ② 上下文总线 | 时钟+太阳状态（纯数学）、天气数据（来自 provider 插件）、指针/前后台事件、季节/节日 |
| ③ 插件注册表 | 扫描目录/工坊订阅目录 → 读 manifest → 校验 → 启停/排序/卡槽仲裁（§3.4） |
| ④ 存储 | localStorage，按插件 id 命名空间隔离 |
| ⑤ 设置中心 | 读各插件 manifest 的 settings schema → 自动生成设置 UI（双语） |
| ⑥ i18n | 字符串表 + manifest 双语字段解析（§6） |

**内核不包含任何具体画面内容**——天空渐变是唯一例外（内置基础层，一切卡片的背景）。

### 3.2 插件分类学（五类）

| 类型 | 内容 | 是否含代码 | 示例 |
|---|---|---|---|
| `card` 素材卡 | 场景元素图（树/山/云/月亮/流星图） | ❌ 纯声明式 | 官方四季山峦包、工坊樱花树 |
| `effect` 效果层 | 粒子/滤镜（雨、雪、雾、光斑） | T1 内置渲染器+参数；T2 可代码 | 雨雪效果插件 |
| `behavior` 行为 | 有状态机的东西（宠物物种、飞鸟、萤火虫） | ✅ 沙箱 JS（T2 开放） | 官方宠物、工坊新物种 |
| `provider` 数据源 | 天气源、节日日历 | ✅ 沙箱 JS（官方先行） | Open-Meteo（默认内置） |
| `preset` 预设 | 卡片组合方案（极简/完整/深夜模式） | ❌ 纯声明式 | 官方三预设、玩家分享配置 |

### 3.3 插件包格式

```
pack.sakura/
  manifest.json      # 附录 B：id/type/api版本/双语名/卡片/设置schema
  assets/*.png       # 带 alpha 素材（4K 长边）
  main.js            # 仅 behavior/provider，T2 前官方专属
```

要点：**素材卡零代码**；卡片声明 = 图层类 + 锚点区 + 变体列表 + （可选）独立深度图。

### 3.4 生命周期与卡槽仲裁

`发现 → 校验（schema+尺寸上限）→ 注册 → 启用/禁用 → 排序`

- **卡槽**（附录 C）：背景槽（内置天空，单实例）／场景槽（山、树…每槽一实例，同槽多包时用户择一）／覆盖层（粒子、彩蛋、宠物，可叠加）
- 三态偏好（auto/show/hide）作用于每个卡实例；冲突矩阵见 §4.2
- 用户可调同类内排序；跨类顺序由内核锁定（保证深度语义）

### 3.5 安全与沙箱（分阶段）

- **T1**：工坊只收声明式包（card/preset）——无代码即无攻击面
- **T2**：开放 behavior/provider 代码：Web Worker + postMessage 结构化绘制指令（不碰 DOM）；无默认网络权限；包体积上限；崩溃隔离（worker 死 = 插件禁用，内核无恙）
- 商店页与工坊页明示内容性质；AI 素材如实披露

### 3.6 自举：官方内容 = 第一批插件

`official-base`（天空+时辰光照调色）、`official-mountains`（T0 程序化山峦迁为声明式数据）、`official-weather`（雨雪粒子+Open-Meteo provider）、`official-pet`（宠物）、`official-presets`（三预设）。**T0 原型的 uniform 开关方案在 T1.1 重构为插件数据驱动**——概念已验证，重构是机械工作。

### 4.2 卡片系统与冲突仲裁

三态偏好：`跟随真实(auto) / 强制(on,show) / 关闭(off,hide)`，作用于每个卡实例。**核心原则：元素卡消失，世界照常运转**——光照是世界的属性，不是太阳圆盘的属性。

| 用户设置 | 真实上下文 | 结果 |
|---|---|---|
| 太阳卡=隐藏 | 晴天正午 | 无圆盘，天空仍按正午变亮 |
| 雨=跟随 | 下雨 | 雨粒子 + 云量增加 + 日月自动隐去 |
| 云卡=隐藏 | 下雨 | 装饰云消失，雨照下（粒子属天气系统层） |
| 时间=锁定 21 点 | 真实白天 | 自由模式：夜景氛围 |

### 4.3 时辰光照（T0 已验证）

赤纬 δ=23.44°·sin(2π(284+N)/365)；高度角 e=asin(sinφ·sinδ+cosφ·cosδ·cosH)；调色板关键帧挂 e∈{-90,-12,0,8,25,60}°；月亮=反日点近似。时辰光照是**官方基础插件**（`official-base`）而非内核——内核只提供上下文总线。

### 4.4 天气系统（provider 插件）

- 默认 `provider.open-meteo`：免费无 key，城市手选（隐私友好），30 分钟缓存，失败静默沿用
- 天气 → 云量/粒子类型/调色偏移/日月可见度/宠物行为
- T0 手动"晴/雨"演示同管线；T2 可出第三方 provider（日历/节日/股行情？不在范围）

### 4.5 精灵宠物（官方 behavior 插件）

- 深度排序进场景（走树后/山脊后探头）——带深度图壁纸独有
- 上下文人格化：雨天打伞躲树下、深夜趴睡、冬季围巾
- 注意力红线：全屏自动睡、夜间低活动
- v0：1 只、5 态（idle/walk/curious/sleep/shelter）、抚摸+喂食、命名空间存储
- 动画：部件化精灵+参数形变（Live2D 思路），不做逐帧
- 养成/进化/多物种 → T2（工坊新物种=第三方 behavior，随沙箱开放）

### 4.6 设置中心与预设

- 双栏：左=插件列表（启停/排序/变体），右=选中插件的设置（manifest schema 自动生成）
- 官方预设插件：极简（只留光照）/ 完整 / 深夜护眼
- 配置 S 见附录 A；`lw.cfg.v1` + 各插件 `lw.p.<id>.v1`

### 4.7 性能与功耗

30fps 上限（15/30/60 可调）、DPR≤1.5、hidden 跳帧、low-power 上下文；全屏时暂停合成（壳层检测）；挂机 GPU<5%；单 JS 体积红线 >3000 行引 esbuild。

## 5. 技术方案

### 5.1 技术栈（锁定）

| 层 | 技术 | 备注 |
|---|---|---|
| 语言 | TypeScript/JS 一门（现 JSDoc 零构建） | Go 已否决（浏览器交付=只有别扭的 WASM 路） |
| 壳 | **Tauri 2**（Rust 由 AI 代写，用户只碰配置） | Neutralino 否决：WorkerW 嵌入+Steamworks 需要真原生层 |
| 壁纸嵌入 | Win32 WorkerW 窗口 + WebView2 子窗口（Lively 同款思路） | T1.0 spike 首要验证点 |
| 渲染 | WebGL2 + GLSL | — |
| Steam | steamworks-rs：ISteamUGC（工坊订阅/安装）、成就（T2） | 每款 App $100 上架费 |
| 沙箱 | Web Worker + postMessage 结构化指令 | T2 开放第三方代码 |
| 资产生成 | 云端：LiblibAI/即梦（图）、HF Spaces（Depth-Anything） | 零本地 ML |
| 构建 | 无 → esbuild（>3000 行触发） | — |
| 托管 | GitHub + Pages（开发预览）；国内镜像 Cloudflare（T1.3 可选） | — |

### 5.3 渲染层

- 图片卡模式：`uv' = uv - mouse·par·depth`（v1 UV 位移；v2 多步采样消遮挡），先微放大防露边
- 天空=内核内置基础层；一切卡片按图层类合成（附录 C）
- 官方山峦：T0 程序化实现迁为"程序化渲染器+声明式参数"插件（保留零素材可用性）

### 5.4 上下文层

时钟/太阳纯数学无网络；三级时辰优先：URL 调试 > 面板锁定 > 真实；天气经 provider 插件进总线，消费方（渲染/宠物/预设）只订阅事件。

### 5.5 数据与存储

`lw.cfg.v1`（全局 S）+ `lw.p.<pluginId>.v1`（插件命名空间）；无账号云同步；工坊订阅清单可导出分享（=preset 包素材）。

### 5.6 资产管线（= 插件包构建管线）

```
风格包源（提示词规范→LiblibAI/即梦出图→人工筛→HF Spaces 深度图）
  → pack 打包器（写入 manifest：双语名/卡槽/锚点/变体/设置schema）
  → 官方捆绑 or 工坊上传
```

- 构图规范：强前/中/远分层、前景主体、避免人脸（深度估计易崩）
- 季节一致性：春为基准 img2img/ControlNet 锁构图
- 素材留档（prompt+来源）备 Steam 披露审查

### 5.7 Steam 集成（D8 核心）

- Steamworks 合作伙伴账号（$100/款）；商店页**双语**（简中+英文）+ AI 内容披露如实勾选
