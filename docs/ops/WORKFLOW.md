# 协作与流程（WORKFLOW）

## 0 本文件管什么 / 不管什么

- **管**：AI 与用户的分工、文档纪律（谁先谁后）、提交规范、评审闸门（哪些事必须用户裁决）、**新会话的进入方式与禁止事项**。
- **不管**：环境安装（见 [`ENV.md`](ENV.md)）；设计与规格本身（见 [`../charter/GDD.md`](../charter/GDD.md)）。

---

## 1 分工（AI ≈ 85% / 用户 ≈ 15%）

| 角色 | 负责 |
|---|---|
| **AI** | 全部 C++ 与配置、全部脚本（PowerShell）、文档、数据 JSON、生图调度与批量生成、编译与自测、蓝图逐条说明书 |
| **用户** | ① 批准并运行安装脚本；② **手动登录 Epic 账号**；③ 在 Launcher / 编辑器 GUI 里做不可脚本化的选择；④ **审美裁决与挑图**；⑤ 立项 / 数值走向 / 风格定标的拍板 |

**用户必须亲自做的四件事**（其余交给 AI）：安装与登录、GUI 选组件与路径、编辑器里连蓝图、看图拍板。

> **原则**：凡可代码化或脚本化的环节默认由 AI 完成；编辑器只保留不可脚本化的可视化决策（GDD §0 分工比例）。

---

## 2 文档纪律

1. **文档先行**：接口、规格、目录结构变化**先改文档再改代码**（README §六）。
2. **索引必须同次更新**：任何文档的新增 / 作废 / 迁移 / 版本变化，**必须在同一次提交内**更新 [`../INDEX.md`](../INDEX.md) 的状态矩阵。
3. **真源唯一**：全仓只允许一个 `truth: owner`（[`../charter/GDD.md`](../charter/GDD.md)）；出现第二个即视为缺陷。
4. **结构描述带状态**：写目录树必须标 `现状` / `计划`，禁止把计划写成存在。
5. **一种事务一份文档**：不要把规格、计划、环境、流程混写进同一份文件（见 [`../INDEX.md`](../INDEX.md) §0）。

---

## 3 提交规范

| 项 | 规则 |
|---|---|
| 语言 / 语气 | **英文、简短祈使句**（与仓库历史一致）；不加 emoji |
| 粒度 | 小步提交、频繁同步；一次提交只做一件事 |
| 文档与代码 | 同一次改动产生的文档与代码**同一次提交**（"文档先行"不等于"分开提交"） |
| 素材 | 卡面 / 立牌 / 风格图**单独提交**（便于回溯与回退） |
| 派生文件 | `Intermediate/`、`Binaries/`、`*.sln`、`compile_commands.json`、`Content/**` 二进制**不入库** |
| 不 force push | `main` 禁止强推（`origin` 是异地备份，强推会毁备份） |

---

## 4 评审闸门（必须用户裁决的五处）

| 闸门 | 何时 | 判据 |
|---|---|---|
| **1 风格定标** | 每个风格主题上线前 | 出**正午 / 黄昏 / 雨**三张对照图，用户裁决锁定；对不上 = 退回（[`../art/ART-STYLE.md`](../art/ART-STYLE.md) §6） |
| **2 素材挑图** | 每批生图产出后 | 按 QC 清单逐条过 + 用户挑图；未挑中的不写 `pick=yes`（[`../art/ASSETS.md`](../art/ASSETS.md) §4） |
| **3 里程碑验收** | M0 / M1 / M2 完成时 | 按验收标准逐条核对，**13 条里的人工项必须用户点头**（[`../plan/ROADMAP.md`](../plan/ROADMAP.md) §2） |
| **4 立项与规格变更** | 任何时候 | 改 `GDD.md` §0–§3（定位 / 非目标 / 核心循环）必须用户确认；AI 不得单方面改立项 |
| **5 开放问题裁决** | 甲方提出时 | 从 [`../charter/OPEN-QUESTIONS.md`](../charter/OPEN-QUESTIONS.md) 取，裁决结果记入 [`../charter/DECISIONS.md`](../charter/DECISIONS.md) |

> **反向约束**：AI 在这些闸门之外**不要停下来等确认**；能自己查证的（目录、命名、技术方案）自己定，只把"影响立项 / 审美 / 数值走向"的事交给用户。

## 5 git 约定（单机开发）

**单机开发**（2026-10-16 起；旧双机协作模式已废止，归档见 [`../archive/SYNC-v1.1.md`](../archive/SYNC-v1.1.md)）：

- git 只承担**版本管理与历史回溯**；`origin`（GitHub）作为**异地备份**并触发 CI 自检。
- **未提交视为未落地**；小步提交，素材类改动单独提交（§3）。push 不再有时效义务，按里程碑 / 阶段推送即可。
- `main` 禁止 force push；不使用定时同步计划任务。
- Content 大资产不入 git、可由"种子 + 生成器 + 契约 + manifest"重建——见 [`../tech/STRUCTURE.md`](../tech/STRUCTURE.md) §9。

## 6 新会话进入方式（AI 自用清单）

**第一步（约 3 分钟）**：

1. 读 [`../INDEX.md`](../INDEX.md)（状态矩阵 + 硬规则）。
2. 读 [`../charter/GDD.md`](../charter/GDD.md) §0–§3（立项 / 定位 / 非目标）。
3. 读 [`../plan/ROADMAP.md`](../plan/ROADMAP.md) §1 + §5（当前阶段与执行计划）。
4. 按任务域读对应文档（[`../INDEX.md`](../INDEX.md) §0 的事务域表）。

**禁止事项（历史踩坑清单）**：

| 禁止 | 原因 |
|---|---|
| 把已作废形态的技术带回现行文档或方案 | 2026-10 形态已换：不要提 **Tauri / WebGL / Vite / TypeScript / 2.5D / 自走棋 / 卡牌收集**；`app/`、`studio/`、`shared/` 旧内容已删除或为计划中 |
| 引用归档稿当作依据 | `../archive/**` 无约束力（[`../archive/README.md`](../archive/README.md)） |
| 引入计划外的引擎插件 / 第三方中间件 | 依赖要经用户确认；引擎内插件只补经市场核实的（GDD 第 8–9 轮裁决） |
| 在运行期调用 AI | 明确非目标（GDD §2） |
| 把设定/数字凭印象写进文档 | 规格以 GDD 为准；数字必须可核对 |
| 让 `Sim`（纯逻辑）依赖渲染 / 蓝图 | 硬约束（[`../tech/ARCHITECTURE.md`](../tech/ARCHITECTURE.md) §2.2） |
